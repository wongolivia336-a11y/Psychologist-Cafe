# 3D asset decision record

当前状态：阻塞。2026-10-26 在本工作区检查时没有可调用的 Blender 可执行文件，也没有现成的 `.blend`、`.glb` 或 `.gltf` 资产，因此没有生成真实餐盘、玻璃杯、纸张或怀表资产。

当前代码里的实时实验是 `ThreeStillLife.tsx` 的原生 Three.js 程序化几何，不是 R3F，也没有加载 GLB；`Dish.tsx` 仍保留 Canvas 静物作为无 WebGL 回退。没有把这段程序化几何或浏览器截图当作 Blender 资产交付。

## 资产验收清单

- 固定机位、真实比例关系和清晰的透明玻璃边缘。
- 盘面、杯壁、纸张和怀表的材质区分；避免把食物识别成重量、热量或身体评价。
- 低面数移动端版本、贴图尺寸上限、无动画 fallback 截图。
- 每个物件都能导出为 glTF/GLB，并保留来源、许可证和 Blender 版本记录。

## 方案比较（当前为架构判断，未做性能实测）

| 维度 | 实时 R3F / Three.js | Blender 固定机位预渲染 |
|---|---|---|
| 材质质量 | 可交互、可动态改材质；移动端受 shader、纹理和 GPU 约束 | 固定画面更容易稳定出玻璃、纸张和金属质感 |
| 首次加载 | 需要下载 GLB、纹理和运行时；可懒加载 | 只需加载图片/序列帧，首次成本更可控 |
| 移动端性能 | 需要控制 draw call、像素比和 GPU 内存；当前只有浏览器可用性回归，没有 FPS/内存实测 | 通常更稳，但失去实时旋转和逐物件交互 |
| 交互成本 | 需要相机、命中测试、资源生命周期和无 WebGL fallback | 交互只保留 HTML 控件，和当前桌边叙事更一致 |
| 回退策略 | Canvas 静物或静态图；当前已有 Canvas | Canvas 静物是现成回退，不依赖 3D runtime |

在 Blender 可用并完成资产、尺寸和移动端实测前，不新增 React Three Fiber 或 Motion，也不把当前原生 Three.js 实验升级成生产资产管线。下一步必须先拿到可追溯的 Blender/GLB 资产，再用同一组视口比较材质、首屏、移动端性能、交互成本和 Canvas 回退。

- Mock / 未验证：GLB 材质质量、首次加载、移动端 FPS、GPU 内存、交互命中成本均未完成实测。
